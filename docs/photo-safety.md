# 사진 보호 검사

이 검사는 사진 파일을 읽기만 한다. 사진의 화질·크기·색·EXIF를 변경하거나 재압축하지 않는다.
첫 기준 목록은 기존 `3ec0d60`의 웹용 파일 103개이며, 지금 사용 중인 고화질 파일을 그대로 등록했다.

## 실행

Python 3.12 이상에서 실행한다.

```sh
python3 -m pip install -r scripts/photo-check-requirements.txt
python3 scripts/check-photo-safety.py
python3 -m unittest discover -s tests -p 'test_photo_safety.py'
git config core.hooksPath .githooks
```

마지막 명령은 현재 로컬 저장소에 푸시 전 검사를 설치한다. 새로 복제한 작업 폴더에서도 한 번 실행해야 한다.
훅은 작업 폴더 대신 **실제로 푸시할 커밋의 파일**을 검사하고, 실패하면 푸시를 중단한다.
검사 의존성이 없거나 검사 자체가 실패해도 푸시는 중단된다. 훅을 우회하지 말고 원인을 먼저 해결한다.

이 저장소에서는 `public/`의 공개 파일을 검사하고, 검토 목록은 `scripts/`에 보관한다.
GitHub의 `Photo safety` 검사는 `doster/**`·`main` 푸시와 `main` 대상 PR에서 자동 실행된다.
`Deploy` 빌드 작업에서도 사진 검사와 실패 탐지 테스트를 먼저 실행한다. 검사에 실패하면 패키징과 서버 배포가 진행되지 않는다.

## 검사 내용

- 새 사진·교체 사진이 검토 목록의 SHA-256 및 크기와 일치하는지
- 실제 파일 형식이 WebP인지, 공유 미리보기만 1200×630 JPEG인지
- EXIF 저작권 문구가 있고 GPS 태그가 없는지
- 메인 사진마다 `images/guard/`에 검토된 360px 이하 보호 사본이 있는지
- HTML에서 사용하는 사진·재질·모델이 존재하고 `?v=`가 실제 SHA-1 앞 8자리인지
- `gallery.html`의 이미지·모델 주소에 버전 해시가 빠지지 않았는지
- RAW·TIFF·PSD 등 제작용 파일, public/ 안에서 이미지 폴더 밖의 미검토 사진, 심볼릭 링크가 추가되지 않았는지
- 두 HTML의 `noai, noimageai` 및 기존 robots 수집 제한이 유지되는지

## 새 사진을 추가하거나 교체할 때

1. 원본은 저장소에 넣지 않는다. 도현이 선택한 화질의 가공된 웹용 파일만 준비한다.
2. 공개용 사진, 3D 사본, 워터마크 보호 사본을 직접 확인한다. 공유 미리보기에는 얼굴을 넣지 않는다.
3. 기존 저작권 문구를 유지하고 GPS를 제거한다. 보호 사본은 실제 워터마크가 있어야 한다.
4. 참조 주소와 내용 해시를 갱신하고, 확인한 파일만 `scripts/photo-safety-manifest.json`의 `assets`에 SHA-256·width·height를 기록한다. 삭제도 참조와 목록을 함께 검토한다.
5. 검사를 통과한 뒤 작업 브랜치에 푸시하고 PR을 만든다. 도현이 반영을 요청한 경우에만 merge commit으로 main에 병합한다.

해시는 **확인한 파일이 그대로인지** 검사한다. 워터마크 글자나 인물 동의를 자동 판별하지 않는다.
검사를 통과시키려고 목록 전체를 무조건 재생성하면 안 된다. 특히 보호 사본은 직접 열어서 워터마크를 확인한 뒤 해당 항목만 갱신한다.
재질(`images/gallery/tex/`)과 모델(`images/gallery/models/`)은 사진 검토 목록에서 제외하지만 형식 및 참조 해시는 확인한다.

## 폰용 작은 사본 (`images/phone/`)

메인 페이지 사진은 폰에서 `images/phone/`의 가로 1440px 사본을 받는다(`srcset`). 태블릿·데스크톱과 크게 보기(뷰어)는 원본을 그대로 쓴다.
첫 화면 `hero.webp`는 폰 화면을 꽉 채워 잘려 보이므로 원본만 쓴다.

- 사본은 `python3 scripts/make-phone-copies.py`로 만든다. 원본은 읽기만 하고, 저작권 EXIF는 그대로 옮기며 GPS는 쓰지 않는다.
- 사본도 검토 대상이다. 직접 확인한 사본만 manifest에 기록한다.
- 사본은 원본의 보호 사본(`images/guard/`)을 같이 쓰므로 따로 만들지 않는다. 검사기는 사본마다 원본이 있고, 더 작고, 비율이 같은지 확인한다.
- 원본을 교체하면 사본도 다시 만들고 `index.html`의 `srcset` 원본 가로 크기도 맞춘다.
